Do you need individual petal files?

No — not for these animations. The in-app mark is already four independent vector paths. This page uses the same outlines and palette as Services/AppLogo.cs:

  • Top-left / bottom-right: main-diagonal leaf (sharp corners on the ↘ diagonal), fills #FF0A76→#FFD510 and #F1067E→#1A65B5.
  • Top-right / bottom-left: anti-diagonal leaf, both #2CD098→#1D4ADB.
  • Each petal is a 23.4-unit square, corner radius 46.6% of the edge, separated by a 1.2-unit cross gap.

WinUI already animates each petal’s own composition visual (rotate, scale, opacity) plus the whole mark. Anything in this catalog ports as more composition animations on those four paths — not as four PNGs.

Separate petal SVGs would only help if you wanted to redraw the leaves in a design tool. They would not unlock a motion that the current geometry cannot do.

What “all possible” means here

Four independently transformable petals, plus the group, give a finite set of motion families rather than an infinite grid of delay × easing × property. This catalog covers every family that still reads as the SwiftX mark:

  • Assemble / dismiss — stagger order (clockwise, pairs, together) × property (scale, twist, fade, translate).
  • Idle — breathe, chase, pinwheel, gap, loader, highlight (maps to hot corners).
  • Interactive — hover a leaf, pick a corner, magnetic follow.

Home wants two complementary motions so Orbit and Tools do not look like copies — that is why the shipping pair is unfurl vs pulse. Split to orbit is the one that literally becomes the dock: eight bubbles, 45° apart, hub in the middle. Pair it with a Tools motion from the Tools mockups page (pretty-print, pipeline, encode) rather than another pinwheel.
