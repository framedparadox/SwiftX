Support

Feedback, suggestions & requests

Found a bug? Have an idea? Want to request a feature? Here is how to reach us.

SwiftX is open source — your feedback shapes it directly.

Bug reports go to the GitHub issue tracker.
Feature requests and suggestions go to GitHub Discussions.
Quick feedback or a store rating can go to the Microsoft Store.
Nothing you write there passes through SwiftX.
  1. Report a bug
  2. Request a feature or enhancement
  3. Share a suggestion
  4. Rate or review on the Microsoft Store
  5. Attach a diagnostic log
  6. Send feedback by email
  7. A note on privacy

1. Report a bug

The best place to report something that isn't working is the GitHub issue tracker. Before opening a new issue, search to see whether someone else has already reported the same thing.

A useful bug report includes:

  • What you expected to happen, and what happened instead.
  • The steps that reproduce it reliably, or when it first appeared.
  • Your Windows version (Settings → System → About) and whether SwiftX is installed from the Microsoft Store or built from source.
  • The diagnostic log from %TEMP%\swiftx.log — SwiftX recreates it on every launch, so it covers the most recent session. Attach it to the issue rather than pasting it inline.

Open a bug report on GitHub

2. Request a feature or enhancement

New feature requests live in GitHub Discussions — Ideas. Describe the problem you are trying to solve, not only the solution you have in mind. That helps evaluate whether there is a better fit already, or whether the request touches something planned.

Before posting, search existing discussions to see whether the same idea has already come up. Upvoting an existing request carries more weight than opening a duplicate.

Request a feature on GitHub

3. Share a suggestion

For ideas that don't fit neatly as a feature request — a wording change, a UX tweak, a question about direction — use GitHub Discussions — General. These are read and considered, even when they don't result in an issue.

Start a discussion on GitHub

4. Rate or review on the Microsoft Store

If you installed SwiftX from the Microsoft Store, a rating or review there helps other people find it and signals what matters to users. You can also open the Windows Feedback Hub from Settings → About → Feedback & rating → Share feedback inside SwiftX.

Rate SwiftX on the Microsoft Store

5. Attach a diagnostic log

SwiftX writes a diagnostic log to %TEMP%\swiftx.log. It is recreated on every launch and covers events from the most recent session: window activation, shortcut registration, hot-corner detection, and failures that might not surface any other way.

To find it, press Win R, type %TEMP%\swiftx.log, and press Enter. Attach the file to a GitHub issue rather than pasting its contents inline.

The log records only what SwiftX itself does. It does not contain your files, keys, or any values from Secure values.

7. A note on privacy

When you open a GitHub or Microsoft Store link from this page or from inside SwiftX, you are visiting a third-party service. SwiftX does not see what you type there, and nothing passes through SwiftX on the way. GitHub and Microsoft's own privacy statements apply to those services.

For a full description of what SwiftX itself does and doesn't do with your data, see the privacy policy.
